The corpus is hundreds to thousands of the top packages and libraries for each
language, ranked and downloaded rather than hand-picked. `treebank rank` builds the list and
`treebank fetch` retrieves it. Choosing the files by hand would mean choosing
the code the grammar already handles.

Each language has a lockfile pinning exactly which packages, versions and
files were measured. `treebank hydrate` rebuilds that corpus from the lock, so
a sweep run next year measures the same thing as one run today.

## The ledger

Results are committed next to the grammar rather than reported. Each grammar's
`ledger.toml` records what was measured, against which grammar revision, with
which oracle — and the pass rate on its page comes from there.

Two things follow. Sweep results are regenerated by running the sweep, never
edited by hand. And when a grammar changes, its evidence is stale until it is
re-run; `treebank status --check` reports that, so staleness is visible rather
than assumed away.

## What a corpus cannot show

Every file in it is valid code. No quantity of correct code can demonstrate
that a grammar rejects what the language rejects, which is why the checks on
the next page exist.
